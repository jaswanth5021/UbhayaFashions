# Security policy

## Reporting a vulnerability

Please do not publish suspected vulnerabilities in public issues, discussions, screenshots, or social media.

Use GitHub's **Private vulnerability reporting** feature on this repository's Security tab when it is enabled. If that option is unavailable, use the Ubhaya Fashions website Contact page and request a private security-reporting channel. Include the affected URL or component, steps to reproduce, impact, and a safe proof of concept. Do not include real customer data, passwords, payment credentials, or live tokens.

We will acknowledge a report as soon as practical, assess severity, coordinate a fix, and agree on disclosure timing with the reporter. Please allow reasonable time for remediation before public disclosure.

## Scope

In-scope assets include the Ubhaya Fashions storefront, admin portal, API, authentication flows, and infrastructure operated for the service. Third-party systems such as Razorpay, Delhivery, email providers, social login providers, and AWS-managed services are not authorized testing targets. Do not perform denial-of-service, social engineering, destructive testing, or access other customers' data.

## Safe-harbor expectations

Good-faith research that follows this policy is welcome. Stop testing if you encounter customer data or service instability and report the finding privately. This policy does not grant permission to access systems or data beyond what is necessary to demonstrate a vulnerability.
